# 데이트봇 MVP 요구사항

## 배경

`date-pick`의 첫 번째 이슈는 연인과의 데이트 기록, 가고 싶은 곳, 기념일, 취향과 제약을 활용해 다음 데이트를 추천하고 실제 데이트 기록을 남기는 MVP를 만든다.

Notion `데이트 아카이브`에는 데이트 후보, 완료 기록, 여행 후보, 기념일이 정리되어 있다. MVP는 Slack 자연어 요청을 받아 Notion 기록 기반 추천과 기록 후보 생성을 제공한다.

AI 기능은 OpenAI API로 구현한다. 서버 운영비는 최소화하며, 기본 실행 환경은 Oracle Cloud Always Free VM으로 둔다.

## 목표

- Slack에서 데이트 추천과 기록 요청을 받을 수 있게 한다.
- Notion `데이트 아카이브`를 MVP의 지식베이스와 저장소로 사용한다.
- 최근 기록, 가고 싶은 후보, 기념일, 날씨, 예산, 반복도를 근거로 최대 3개의 추천안을 만든다.
- 자연어 데이트 기록을 구조화해 Notion에 저장할 수 있게 한다.
- 저장 전에는 사용자가 내용을 확인하고 승인할 수 있게 한다.
- OpenAI API를 사용해 AI 기능을 구현한다.
- 서버 운영비는 0원에 가깝게 유지하되, OpenAI API 사용량 기반 비용은 허용한다.

## 사용자

- 주 사용자: 연인과의 데이트 기록과 다음 데이트 계획을 관리하려는 개인 사용자.
- 보조 사용자: 같은 Slack DM 또는 비공개 채널에서 추천과 기록을 함께 확인하는 연인.

## 핵심 사용 시나리오

### 데이트 추천

사용자가 Slack에서 `/date-recommend`, `/date-recommend 이번 주말 데이트 추천`, `/date-recommend 성수 말고 새로운 곳`처럼 요청한다. MVP 기본 추천 명령은 `/date-recommend`이며, 기존 `/date` command는 사용하지 않는다.

시스템은 Notion의 데이트 후보와 완료된 기록, 기념일, 최근 반복 패턴, 날씨와 예산 조건을 참고해 최대 3개의 추천안을 제시한다. 각 추천안에는 이유, 예상 비용 범위, 확인 필요 사항, Notion 저장 후보 정보를 포함한다.

### 데이트 기록

사용자가 Slack에서 `/date-note 오늘 성수에서 전시 보고 파스타 먹었어. 11만원 정도 썼고 전시는 좋았어.`처럼 입력한다. MVP 기본 기록 명령은 `/date-note`이며, 기존 `/date` command는 사용하지 않는다.

시스템은 날짜, 지역, 활동 유형, 비용, 만족도, 메모, 다음 추천 반영 사항을 추출해 저장 미리보기를 보여준다. 사용자가 승인하면 Notion에 저장한다.

### 지식베이스 활용

시스템은 Notion `데이트 아카이브` 페이지를 우선 지식베이스로 사용한다.

- URL: https://jun-n.notion.site/2f32d61b14f080fb8c1dc2fa1d620fa9?source=copy_link
- 확인된 상위 페이지: `데이트 아카이브`
- 확인된 데이터베이스: `데이트`, `기념일`
- 확인된 분류 또는 상태: `데이트`, `여행`, `완료 ㅎ`
- 확인된 예시 항목: `모란시장 투어`, `호캉스`, `한강`, `찜질방`, `제비다방`, `독립영화관`, `바 (Bar)`, `게임`, `야구장`, `북카페`, `롯데월드`, `글램핑`, `일본`, `제주도`, `동해`, `계곡`, `경주`

## 범위

### MVP 포함

- Slack 일반 App/Bot을 통한 요청 수신
- Slack Slash Commands `/date-recommend`, `/date-note` 수신
- Notion `데이트 아카이브` 조회
- Notion 데이트 기록 저장 후보 생성
- 사용자 승인 후 Notion 저장
- 날씨 정보를 고려한 추천
- 최대 3개의 추천안 생성
- Oracle Cloud Always Free VM 기반 실행
- OpenAI API를 통한 추천 및 기록 구조화

### MVP 제외

- 공개 Slack 채널 운영
- 영화관별 실시간 상영시간표 자동 수집
- 식당 예약 가능 여부 자동 확인
- 월간 리포트
- 자동 주간 추천
- `/date-plan` 기반 데이트 계획 생성. 이 기능은 Issue #2에서 별도로 구현한다.
- 장기 대화 원문 저장
- 복잡한 머신러닝 학습 모델

## 데이터 요구사항

### 데이트 기록

데이트 기록에는 최소한 다음 정보가 필요하다.

- 날짜
- 제목
- 지역
- 활동 유형
- 실내/실외 여부
- 비용
- 만족도 또는 감정
- 메모
- 다음 추천에 반영할 힌트

### 데이트 후보

데이트 후보에는 최소한 다음 정보가 필요하다.

- 이름
- 지역
- 유형
- 예상 비용
- 실내/실외 여부
- 우선순위 또는 상태
- 출처 링크
- 비고

### 기념일

기념일에는 최소한 다음 정보가 필요하다.

- 이름
- 날짜
- D-day 또는 남은 기간
- 추천에 반영할 메모

## 외부 연동 요구사항

- Slack은 입력과 응답 UI로 사용한다.
- Slack App 설정의 Slash Commands에는 `/date-recommend`, `/date-note`를 각각 추가한다.
- 기존 `/date` command는 제거하거나 사용하지 않는다.
- 저장/수정/취소 버튼 처리를 위해 Slack Interactivity는 계속 사용한다.
- Slack 연결 방식은 Socket Mode를 계속 사용한다.
- Notion은 지식베이스와 저장소로 사용한다.
- 날씨 정보는 추천 근거로 사용한다.
- 장소, 영화, 식당 정보는 MVP에서 확실하지 않으면 `확인 필요`로 표시한다.
- OpenAI API는 추천 문장 생성, 자연어 기록 구조화, 후보 비교에 사용한다.
- OpenAI API 호출량은 비용을 예측할 수 있게 제한하고, 필요한 맥락만 전달한다.

## 운영 및 비용 요구사항

- 서버 월 고정비가 없거나 사실상 0원인 구성을 우선한다.
- 기본 실행 환경은 Oracle Cloud Always Free VM처럼 월 고정비가 없거나 사실상 0원인 서버를 우선한다.
- OpenAI API 비용은 사용량 기반 비용으로 허용하되, 요청당 token 사용량을 줄이는 방식을 고려한다.

## 안전 및 개인정보 요구사항

- Slack은 DM 또는 비공개 채널 사용을 기본으로 한다.
- Notion integration 권한은 데이트 관련 페이지와 데이터베이스로 제한한다.
- Notion 쓰기 작업은 사용자 확인 후 수행한다.
- API 키와 토큰은 코드에 하드코딩하지 않는다.
- 대화 원문 전체를 장기 저장하지 않고, 필요한 구조화 정보만 저장한다.
- 변동성이 높은 정보는 확실한 것처럼 표현하지 않는다.

## 완료 조건

- Slack에서 `/date-recommend` 추천 요청을 받아 최대 3개의 추천안을 반환한다.
- 추천안은 Notion 기록 또는 후보, 날씨, 예산, 반복도 중 최소 3개 이상의 근거를 포함한다.
- Slack에서 `/date-note` 자연어 기록 요청을 받아 Notion 저장 미리보기를 생성한다.
- 사용자가 승인하면 Notion에 기록이 저장된다.
- 서버 월 고정비 없이 운영 가능한 실행 방식이 검증된다.
- OpenAI API를 사용한 추천과 기록 구조화가 동작한다.
- API 키와 토큰이 코드에 노출되지 않는다.

## 미정 사항

- 실제 운영용 OpenAI API 모델
- 날씨 API 제공자
- 실제 Slack/Notion/OpenAI token 기반 smoke test
- Oracle VM 프로세스 자동 재시작 방식
